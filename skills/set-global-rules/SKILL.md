# 设置全局协作约定

仅在用户主动调用本 skill 时执行以下流程。

1. 定位 Codex 全局 `AGENTS.md`：设置了 `CODEX_HOME` 时使用该目录下的 `AGENTS.md`，否则使用用户主目录下的 `.codex/AGENTS.md`（Windows 为 `%USERPROFILE%\.codex\AGENTS.md`）。将目标解析为绝对路径，写入范围限于这个全局文件。
2. 读取现有内容；文件不存在时创建父目录及文件。保留已有约定、格式和无关内容。
3. 以最小改动合并下方区块。已有标记区块时仅更新该区块；尚无区块时，在末尾添加缺失的约定，已有相同含义的约定直接复用。重复调用后，规则应保持完整且不重复；内容已满足要求时无需写入。
4. 回读文件并检查差异，确认四条约定均已存在且无关内容保持原样。只自动执行这项最小验证。
5. 简短报告实际修改的绝对路径、添加或已存在的约定。若需要完整、全面的行为测试，等本次全部修改完成后，向用户说明测试范围并请求同意，取得同意后执行。

## 写入内容

```markdown
<!-- set-global-rules:start -->
## 用户协作约定

- 多写正向引导，少写禁令。像正常人一样自然、直接地表达，避免使用“不等于”“不能证明”“不能全部”“不能承诺”“不代表”等否定式套话；直接说明实际情况，完不成时直接说完不成。
- 进行修改任务时使用最小改动。
- 进行设计类任务时，文本内容面向使用者生成，围绕实际内容和操作展开，少用标语和 slogan；设计意图和设计要求通过设计本身体现，交付文案不直接陈述设计意图、设计要求或对设计的解释说明。
- 进行任务时，只自动执行验证当前改动所必需的最小测试；完整、全面的测试等全部工作完成后，再向用户说明测试范围并请求同意，取得同意后执行。
<!-- set-global-rules:end -->
```

若 Codex 主目录中存在非空的 `AGENTS.override.md`，在结果中说明它会优先于 `AGENTS.md` 加载；保留该覆盖文件，按本次请求只更新全局 `AGENTS.md`。
