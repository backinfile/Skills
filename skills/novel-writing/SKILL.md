# 小说写作

## 输入与输出

- 默认只读取用户明确指定的输入文档，不搜索或引用其他现有文档；本次任务生成的文件按下述阶段限制读取。
- 使用用户指定的输出目录；未指定时，以当前工作目录为基准。无需 Git 仓库或特定项目结构。无法确定工作目录时，先询问保存位置。
- 小说文本及对应方案、审查稿放在输出目录的 `drafts/storyNNN/` 下：从 `story001` 起，取已有编号最大值加一，不复用已有目录。
- 独立的写作指南、流程和参考资料放在输出目录的 `docs/` 下，使用带编号的文件名。
- 所有产物保存为 Markdown，保留中间文件，不覆盖或删除已有文件；文件名冲突时递增编号。

## 创作流程

用户要求创作或重写小说文本时，完成以下流程：

1. 保存 v1 写作方案，简述目标、结构、风格、约束，以及需要继承的内容。只记录可供用户审阅的创作安排，不记录内部逐步推理。
2. 完整生成用户要求的全部目标文本，保存为 v1。
3. 对照用户要求审查全部 v1 文本，记录问题及修改建议并保存审查稿。重点检查情节与人物一致性、叙事节奏、语言和要求覆盖情况。审查结果须独立可用：将问题转化为明确的写作约束和改进建议，不复制初稿段落，不使用必须回读初稿才能理解的指代。
4. 第二次生成仅以用户原始输入（含明确指定的素材与补充要求）和审查结果为依据，先保存 v2 写作方案，再从头完整生成全部目标文本并保存为 v2。不得读取或沿用 v1 正文、v1 写作方案及其他第一轮生成内容；v2 写作方案也须仅从上述两类输入导出。

第二次生成应在不含初稿的新上下文中执行：支持独立子代理时，不继承父对话，仅传入本 skill、用户原始输入、审查结果和必要的输出路径。仅停止读取文件不能清除已在上下文中的初稿；无法建立隔离上下文时，说明限制并交付原始输入与审查结果的路径，供新会话继续，不声称已实现隔离。

最终正文只包含用户要求的小说内容，不混入方案、审查、修改说明或其他元文本。仅请求指南、流程、参考资料或审查时，交付对应产物，不自动扩展为小说创作。

## 文件命名

按产出顺序使用两位递增编号，版本号对应正文版本。例如：

- `01-标题_v1_写作方案.md`
- `02-标题_v1.md`
- `03-标题_v1_审查.md`
- `04-标题_v2_写作方案.md`
- `05-标题_v2.md`

每个正文版本都配有独立的写作方案。交付时链接最终正文及中间产物；用户的明确要求优先于以上默认流程和目录约定。
